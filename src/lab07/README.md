# Лабораторная работа №7 — Интерактивное CLI-приложение

**Предметная область:** Недвижимость (квартиры, жилые и коммерческие помещения)

---

## 1. Цель работы

Реализовано полноценное интерактивное консольное приложение для управления коллекцией объектов недвижимости, объединяющее все знания, полученные в лабораторных работах №1–№6:

- **ЛР1** — инкапсуляция, валидация, свойства, магические методы.
- **ЛР2** — класс-коллекция с методами `add`, `remove`, `get_all`.
- **ЛР3** — наследование: `ResidentialApartment` и `CommercialApartment`.
- **ЛР4** — интерфейсы `Printable` и `Comparable` (ABC).
- **ЛР5** — функции-стратегии для сортировки и фильтрации.
- **ЛР6** — аннотации типов (`typing`), типобезопасность.

Приложение имеет трёхслойную архитектуру (CLI → Бизнес-логика → Модели), интерактивное меню из 10 пунктов, обрабатывает некорректный ввод, поддерживает сохранение/загрузку данных в JSON, форматированный табличный вывод, поиск, фильтрацию, сортировку и пользовательские исключения.

## 3. Описание CLI

### 3.1. Пункты меню

Главное меню содержит **10 пунктов**:

| № | Пункт | Описание |
|---|-------|----------|
| 1 | Показать все объекты | Вывод всех объектов коллекции в форматированной таблице |
| 2 | Добавить объект | Создание нового объекта (обычная квартира / жилая / коммерческая) |
| 3 | Удалить объект | Удаление объекта по ID с подтверждением (y/n) |
| 4 | Поиск по атрибуту | Поиск объектов по адресу, статусу, количеству комнат или типу |
| 5 | Фильтрация по условию | Фильтрация по диапазону цен, площади, статусу или типу |
| 6 | Сортировка | Сортировка по адресу, цене, дате добавления или площади (возр./убыв.) |
| 7 | Статистика | Сводная статистика: средняя цена, площадь, распределение по типам |
| 8 | Сохранить данные | Ручное сохранение коллекции в JSON-файл |
| 9 | Загрузить данные | Загрузка коллекции из JSON-файла (замена текущих данных) |
| 10 | Выход | Автоматическое сохранение данных и завершение программы |

### 3.2. Обработка ошибок ввода

- **Неверный пункт меню** — если введено число вне диапазона 1–10, выводится предупреждение и меню показывается снова.
- **Строка вместо числа** — перехватывается `ValueError` с сообщением: *«Ошибка: введите целое число.»*
- **Некорректные значения атрибутов** — валидация на уровне моделей (`TypeError`, `ValueError`) с понятными сообщениями.
- **Дубликат объекта** — выбрасывается `DuplicateItemError` с указанием ID.
- **Объект не найден** — выбрасывается `ItemNotFoundError` при удалении несуществующего объекта.

### 3.3. Сохранение и загрузка данных

- **Формат:** JSON (файл `data.json` в папке с `main.py`).
- **Автозагрузка:** при запуске приложение автоматически загружает данные из файла. Если файл не найден — начинает с пустой коллекции.
- **Автосохранение:** при выходе (пункт 10) данные автоматически сохраняются.
- **Полиморфная сериализация:** каждый объект сохраняет поле `type` (имя класса), что позволяет при загрузке восстановить объект правильного типа (`Apartment`, `ResidentialApartment` или `CommercialApartment`).
- **Ручное сохранение/загрузка:** доступны через пункты меню 8 и 9.

## 4. Демонстрация работы

### Сценарий 1: Запуск → автозагрузка → вывод коллекции

1. Запуск приложения: `python main.py`
2. Если файл `data.json` существует и содержит данные, они загружаются автоматически.
3. Вывод сообщения: *«Автоматически загружено объектов: N»*
4. Выбор пункта 1 — отображение всех объектов в таблице.

### Сценарий 2: Добавление → редактирование/удаление → выход → повторный запуск

1. Пункт 2 — добавление нескольких объектов разных типов.
2. Пункт 3 — удаление объекта с подтверждением (y/n).
3. Пункт 10 — выход (данные автоматически сохраняются).
4. Повторный запуск — данные загружаются, изменения сохранены.

### Сценарий 3: Сортировка с выбором стратегии

1. Пункт 6 — выбор стратегии сортировки (1–4).
2. Выбор направления (1 — возрастание, 2 — убывание).
3. Вывод отсортированной таблицы.

### Сценарий 4: Фильтрация + перехват исключения при некорректных данных

1. Пункт 5 — выбор типа фильтрации.
2. Ввод некорректных данных (например, min_price > max_price) → перехват `ValueError`.
3. Ввод корректных данных → вывод отфильтрованного списка.

## 5. Вывод

В ходе выполнения лабораторной работы были изучены и применены следующие концепции:

1. **Разбиение на модули и слои** — трёхслойная архитектура (модели → бизнес-логика → представление) с чётким разделением обязанностей. CLI не обращается к коллекции напрямую.

2. **CLI-интерфейс** — интерактивное меню с циклом, обработка пользовательского ввода, форматированный табличный вывод, подтверждение опасных операций.

3. **Обработка исключений** — создание и использование собственных классов исключений (`ItemNotFoundError`, `DuplicateItemError`, `StorageError`, `ValidationError`), перехват стандартных исключений (`ValueError`, `TypeError`, `FileNotFoundError`).

4. **Работа с файлами** — сохранение и загрузка данных в формате JSON с полиморфной десериализацией (восстановление правильных типов объектов через поле `type`), автозагрузка при старте и автосохранение при выходе.

5. **Типизация** — полные аннотации типов во всех публичных методах и функциях (`list[Apartment]`, `Optional[Apartment]`, `Callable[[Apartment], Any]`, `dict[str, Any]` и т.д.), docstring'и для всех публичных элементов.

6. **Стратегии сортировки и фильтрации** — функции высшего порядка, передаваемые в сервисный слой, комбинирование стратегий (сортировка по 4 критериям, фильтрация по 4 условиям).
